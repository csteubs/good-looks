# Fix plan — #74: combine Batch's Select all / Select none into one control

**Status:** valid, not done. Small, self-contained.
**Verified:** 2026-08-17, seen in the running browser preview
(`npm run dev:web?view=batch`) — three buttons: `SELECT ALL`, `SELECT NONE`,
`RESET ORDER`.
**Type:** enhancement. No user-visible defect; the stated benefit is fewer
controls and less state to get wrong.

## Where it lives

```
renderer/main/batch-view.tsx:1310-1332
<div className="gl-batch-controls">
  <Btn ...>{tagFilter === ALL_TAGS ? "Select all"  : "Select these"}</Btn>
  <Btn ...>{tagFilter === ALL_TAGS ? "Select none" : "Deselect these"}</Btn>
  {isCustomOrder(tests, order) ? <Btn ...>Reset order</Btn> : null}
</div>
```

Both buttons call the same helper with a boolean:

```ts
commitRows(setSelection(rowOptions, visibleTests, rowDefaults, /* on */ true|false))
```

## The design decision to make first

The obvious shape is a **tri-state master checkbox** in the checklist header —
checked when every visible test is selected, indeterminate when some are,
unchecked when none — that selects all on click and clears on click when already
full. That replaces two buttons with one control that also *reports* state,
which the current buttons do not.

Two things it must not lose:

- **The filter-scoped labels.** Under a tag filter the buttons currently read
  "Select these" / "Deselect these", and the comment at `batch-view.tsx:1317-1319`
  records why: selecting all under a filter ticks only the *visible* tests
  rather than replacing the whole selection, so hidden ticks are not silently
  dropped. A checkbox has no room for that sentence. It needs an `aria-label`
  and a `title` that say which set it acts on, and the tri-state must be
  computed over `visibleTests`, not `tests`.
- **`RESET ORDER` stays a button.** It is a different verb on a different piece
  of state and is already conditional on `isCustomOrder`.

## Implementation notes

`renderer/ui/controls.tsx:22` wraps Radix's `Checkbox`, which supports
`checked="indeterminate"` — but the `Indicator` at line 31 renders only a check
mark. An indeterminate master checkbox needs a dash glyph for that state, added
to the shared `Checkbox` or passed in. **Adding it to the shared component
changes every checkbox in the app**; adding it locally to Batch does not. Prefer
local unless a second caller exists.

## The test

`renderer/main/batch-view.test.tsx`. Assert the three states — none selected,
some selected, all visible selected — and that clicking under an active tag
filter leaves hidden tests' selection untouched. That last one is the property
the current comment protects and the one a rewrite is most likely to lose.

**Verify it can fail:** make the tri-state read `tests` instead of
`visibleTests` and confirm the filter test goes red.

## Surface area

Net reduction: two controls become one, and the "is everything selected?"
question stops being something the user answers by scanning rows. No new
dependency, no new IPC, no backend change.
